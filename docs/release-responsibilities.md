# Release responsibilities

All workstreams are now authorized under this project-completion branch. The
following are operational roles, not claims that a teammate has signed acceptance.

| Role | Deliverable / continuing responsibility |
| --- | --- |
| Implementation maintainer | Source, tests, image/chart recipe, version/schema compatibility and exact supported scope |
| Lab operator | Approved cluster/node, audit policy/export, isolated namespace, model endpoint, encrypted disk and registry access |
| Human reviewer | Exact action hash/diff, residual-risk choice, separate optional recovery consent and outcome acknowledgement |
| Backup custodian | Daily schedule/30-day retention target, independent archive/backup copy, separate key recovery, measured restores and post-restore reconciliation |
| Two evaluation reviewers | Independently validate ambiguous labels/behavior evidence, reconcile disagreement and attest the frozen dataset hash |
| Independent reproducer | Install from the tagged candidate and run the documented demo/reset without undocumented source edits |
| Report owner | Add actual university hardware/results, review-effort measurements, screenshots and measured failures; submit report/slides |

Private reviewer tokens, audit originals, keys and model weights remain ignored
under data/. Frozen evaluator assertions live outside runtime images and mounts.
No automatic process may impersonate the human reviewer or evaluation signatories.
Local candidate tags and test results do not constitute university sign-off.
